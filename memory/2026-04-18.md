# 2026-04-18

- Ran a targeted source-quality audit after Nat flagged too many non-credible news sources in the pipeline.
- Recent event logs showed repeated low-cred offenders including `fxstreet.com`, `ad-hoc-news.de`, `manilatimes.net`, `bloomingbit.io`, `marketscreener.com`, `insidentity.com`, `bitcoinworld.co.in`, `stocktitan.net`, `news.futunn.com`, and `heygotrade.com`.
- Hardened source filtering in `scripts/config.py` and `scripts/fetch_news.py`: added a conservative `TRUSTED_SOURCES` allowlist, expanded the blocklist for recurring junk domains, switched source matching from loose substring checks to normalized domain-aware matching, and added a source-quality gate so untrusted domains cannot dominate a query when trusted coverage is already available.
- Improved Finnhub source labeling so the pipeline prefers the underlying publisher name over the `finnhub.io` wrapper when Finnhub provides it.
- Added a first-pass official document ingestion layer via `scripts/official_docs_fetcher.py`, which pulls recent SEC filings and same-host IR documents into a normalized schema (`title`, `url`, `source`, `published_at`, `doc_type`, `text_snippet`, `origin`, `form_type`).
- Wrote `research/architecture/official-doc-ingestion.md` to define the next steps toward exchange-specific adapters (HKEX, TDnet/JPX, RNS, SEDAR+) and eventual storage/diffing.
- Fixed Standard Chartered `ir_page` metadata in `scripts/config.py` to `https://www.sc.com/en/investors/financial-results/`, which the new document fetcher can scrape successfully.
- Added a metadata-driven adapter interface in `scripts/official_source_adapters.py` for SEC, LSE, HKEX, and TSE, plus a live probe harness in `scripts/official_docs_probe.py`. Ran live endpoint tests for STAN, HSBC, JPM, AIA, and GOOG and saved the site-specific storage/access learnings in `research/architecture/official-source-site-learnings.md`.
- Durable source learnings from the probe run: use SEC as the primary official-source backbone for JPM and GOOG; use company IR archives as the practical primary source for STAN, HSBC, and AIA, with STAN files typically under `/uploads/sites/66/...`, HSBC results files under `/-/files/hsbc/investors/hsbc-results/<year>/<period>/pdfs/...`, and AIA investor files under `/content/dam/group-wise/en/docs/investor-relations/<year>/...`.
- Current limitation: the SEC adapter is live for document fetching, while LSE, HKEX, and TSE adapters are currently endpoint probes plus URL/storage templates rather than full historical collectors.
- Built a local official-document corpus manager (`scripts/official_doc_corpus.py`) and browser UI (`council_ui/official_docs_server.py`). The system stores files under `/mnt/c/Users/natba/OneDrive/@ Cowork/openclaw-investing-context`, indexes runs and documents in SQLite, supports incremental vs backfill runs, records per-company site-learning notes, and exposes a local web UI to browse docs, monitor progress, and trigger new scrapes.
- Pinned the next architecture priorities for the corpus after reviewing external PDF/XLSX pipeline notes: keep a deterministic HTTP-first core; treat OpenClaw as the control plane, not the transport plane; add a proper source registry, parser/normalization workers, manifest-level version/delta tracking, and an explicit Playwright fallback lane rather than a browser-first design.
- Incremental update from the latest architecture note: no major thesis change, but the crawler decision is now clearer, use `Scrapy + HTTPX + Playwright fallback` if the source mix stays mostly public and Python-friendly, or `Crawlee + HTTPX + Playwright fallback` if the source mix becomes more JS-heavy or auth-heavy.
